# i18n Language Switching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add EN/TH/CN runtime language switching to the webview UI with a dropdown in the header, persisted to localStorage, default English.

**Architecture:** All i18n logic lives inside the webview JS block in `extension.js`. A `TRANSLATIONS` object maps semantic keys → `{en,th,cn}`. A `t(key,vars?)` helper returns the active language string. `renderAllText()` updates every DOM node. No new files, no build step.

**Tech Stack:** Vanilla JS (webview), VS Code Extension API, localStorage

        var _lang = (function() { try { return localStorage.getItem('tinker_lang') || 'en'; } catch(e) { return 'en'; } })();

        function t(key, vars) {
            var s = (TRANSLATIONS[key] && (TRANSLATIONS[key][_lang] || TRANSLATIONS[key]['en'])) || key;
            if (vars) Object.keys(vars).forEach(function(k) { s = s.replace('{' + k + '}', vars[k]); });
            return s;
        }

        function applyLang(lang) {
            _lang = lang;
            try { localStorage.setItem('tinker_lang', lang); } catch(e) {}
            renderAllText();
        }
