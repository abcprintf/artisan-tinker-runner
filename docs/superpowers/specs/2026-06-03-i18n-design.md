# i18n Language Switching — Design Spec

**Date:** 2026-06-03  
**Feature:** Internationalization (EN / TH / CN) with runtime language switching  
**Scope:** Full UI — all buttons, labels, placeholders, tooltips, status messages, tutorial steps

---

## Architecture

All i18n logic lives entirely inside the webview JS block within `extension.js`. No new files, no build step, consistent with the single-file architecture.

### TRANSLATIONS object

A single `TRANSLATIONS` constant at the top of the webview JS maps semantic keys to `{en, th, cn}` string values.

```js
var TRANSLATIONS = {
  'execute':              { en: '▶ Execute in Tinker', th: '▶ รัน Tinker',       cn: '▶ 执行 Tinker' },
  'stop':                 { en: '■ Stop',              th: '■ หยุด',              cn: '■ 停止' },
  // … all keys listed in Translation Keys section below
};
```

### Language state

```js
var _lang = localStorage.getItem('tinker_lang') || 'en';
```

### `t(key, vars?)` helper

```js
function t(key, vars) {
  var s = (TRANSLATIONS[key] && TRANSLATIONS[key][_lang]) || (TRANSLATIONS[key] && TRANSLATIONS[key]['en']) || key;
  if (vars) Object.keys(vars).forEach(function(k) { s = s.replace('{' + k + '}', vars[k]); });
  return s;
}
```

Falls back to `en`, then to the raw key — so missing translations never break the UI. Supports `{placeholder}` substitution for dynamic strings.

### `applyLang(lang)`

```js
function applyLang(lang) {
  _lang = lang;
  localStorage.setItem('tinker_lang', lang);
  renderAllText();
}
```

### `renderAllText()`

Sets every translatable DOM node using `t()`. Called once on page load and again on every language change.

## Language Dropdown UI

Added in the header row next to the `🪄 Artisan Tinker` title:

```html
<select id="langSelect" style="font-size:10px;padding:2px 4px;border-radius:3px;margin-left:auto;">
  <option value="en">EN</option>
  <option value="th">TH</option>
  <option value="cn">CN</option>
</select>
```

On `change`: calls `applyLang(this.value)`. On load: `langSelect.value = _lang`.

## Data Flow

```
User selects lang → applyLang(lang)
  → _lang updated
  → localStorage('tinker_lang') saved
  → renderAllText() called
      → every static DOM node updated via t(key)
      → TUTORIAL_STEPS titles/descs rebuilt from t()
      → history dropdown default option updated
      → templates list re-rendered if visible
```

On webview load:
```
_lang = localStorage.getItem('tinker_lang') || 'en'
langSelect.value = _lang
renderAllText()
```

---

## Error Handling

- `t()` always returns a string — falls back to `en` then raw key
- `localStorage` unavailable → `_lang` defaults to `'en'` silently (try/catch not needed; VS Code webviews always have localStorage)
- `applyLang` with same value is idempotent
